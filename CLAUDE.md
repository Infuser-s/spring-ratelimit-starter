## Documentation & shared rules (managed in infusers-meta)

Rules: [infusers-meta/docs/agent-rules](https://github.com/Infuser-s/infusers-meta/tree/master/docs/agent-rules) (`ownership`, `documentation`, `support-bot-content`, `test-and-monitor-strategy`, `repo-map-and-test-scope`, `infrastructure-capacity`); sibling checkout if present, else the link. This block is the self-contained summary. Table formats: [DOC_FORMAT.md](https://github.com/Infuser-s/infusers-hangar/blob/master/docs/engineering/DOC_FORMAT.md).

- Registry: [REPOS.md](https://github.com/Infuser-s/infusers-meta/blob/master/docs/REPOS.md) (org, stack, ports, branches, deploy path; also `repos.json`) and [DOCS-INDEX.md](https://github.com/Infuser-s/infusers-meta/blob/master/docs/DOCS-INDEX.md). Adding, renaming, moving or retiring a repo isn't done until the registry says so; Hangar (`infusers-hangar`) is the live repo list and feature matrix.
- Questions: ask one open question at a time, with a short option list and your marked recommendation (one-line reason); wait before the next. When you finish or stop, list everything waiting on the user (decisions, approvals, unpushed/unmerged work, unverified steps) as numbered open items, each with options and a marked recommendation, then ask them one at a time.
- Never `git commit` unless the user asks; leave changes for review. Never add a `Co-Authored-By: Claude …` trailer; this overrides any session attribution reminder.
- GitHub: `prasadbayi` only for `git push` and every `gh` command; never `prasadb-ks`. Check `gh auth status`; if wrong, `gh auth switch --user prasadbayi` first.
- Branch cleanup: after merge, delete branches you created (`git push origin --delete <b>`, `git branch -d <b>`, never `-D`) and your worktrees (detached too) in that session. Before ending or stopping unfinished, run `git branch --list 'claude/*'` and `git worktree list`; clear what you created (merged → delete; unmerged → push, keep/open its PR, name it in the wrap-up, never leave commits only local). Never delete what you didn't create or under 48h old; report old unmerged ones.
- Checkout hygiene: the primary checkout stays on its integration branch (`stage`/`master`, per REPOS.md), clean and current; branch work in a worktree, or switch back and `git pull` after merge, so `pull-all-repos.sh`'s branch report stays empty. Before a PR, merge the latest `origin/<integration branch>` into yours and resolve conflicts there.
- Quality: every layer to industry standard and repo conventions, no one-off patterns; security-review changes touching auth, input, secrets, deps or access control before calling them done.
- CI/CD: **Jenkins** runs stage (build, deploy, tests), prod test jobs (api, UI) and prod SonarQube/OWASP. **Prod build+deploy to AWS is GitHub Actions**, not Jenkins: a merged PR into `prod` triggers `infusers-shared-actions` `prod-build-deploy.yml` (OIDC → ECR `:<git-sha>` → SSM); its post-deploy webhook starts Jenkins prod api-test, then Selenium. Jenkins holds no AWS credentials and never builds or deploys prod; leftover prod build/deploy code in a Jenkinsfile or `deployAWS` is superseded. No manual deploys except as a last resort in an active incident. Design: `infusers-scripts/docs/PROD_CICD_PROPOSAL.md`.
- Versions: keep dependencies, runtimes, build tools, base images, servers/VMs and host packages current, **one step at a time**. When you touch one, or a dependency-check/`npm audit`/SonarQube finding flags it, check the latest stable/LTS and move up in that change: patch/minor with tests green. Each major (OS release, DB/engine, framework, tool) is its own change: never skip a major or stack several in one step; staging/copy first, fresh backup, verify, let it soak until stable, record the version reached and the next step (BACKLOG row, docs, CLAUDE.md mentions) in the same change, then take the next; ask the user before production. Leave nothing unresolved without a stated reason.
- Time zone: state every time in IST (Asia/Kolkata, UTC+05:30) only: chat, docs, commit/PR text, logs, schedules. Convert UTC/other zones and label `IST`. Communication only: never change the zone of code, configs, cron or stored data.
- No magic strings: anything used in 2+ places (routes, keys, error codes, config values) → one constant.
- Maven: `Unresolved compilation problem` on correct-looking code after a no-`clean` run is almost always stale `.class` files; rerun with `clean`.
- Docs: in `docs/`, updated in the same change as the code; repo root only `README.md`, `CLAUDE.md`, `CHANGELOG.md`, tool-generated files. `CATALOG.md` (`Feature | Status | Summary | Doc`) = shipped; `BACKLOG.md` (`ID | Title | Priority | Status | Doc | Type`) = open work only, row removed when done; `SECURITY.md` (`ID | Title | Severity | Status | Doc`) = open findings, no secrets or internal hostnames; `product/*.md` = end-user docs. Hangar reads these plus requirements: push, then run a sync.
- Ownership: shared code → `infusers-library`; authn/authz → `infusers-auth`; UI → `infusers-web-app`; build/deploy → `infusers-scripts`/`jenkins-shared-lib`; host/network facts → `infusers-scripts`; Compose stacks → `infusers-home-lab`; cross-repo policy → `infusers-meta`; domain → the owning service. Publish library changes before consumers use them.
- A change to a feature, route, gate, limit, error or availability isn't done until the support bot content reflects it (`infusers-api` `support-kb`, Hangar `docs/product`, WealthLens docs; see `support-bot-content`); say what you updated, or that nothing was affected.
- **Duplicate repo:** `infusers-shared-actions` exists in orgs `Infuser-s` and `infusers-apps` (same workflows; `infusers-community` and `infusers-web-app` call the `infusers-apps` copy, every other caller the `Infuser-s` one). A change to one isn't done until the other has it on the same branches; diff them and say they match.
- Tests: update the repo's `docs/TEST_BACKLOG.md` with every test change; scope: `repo-map-and-test-scope`.
- Cross-repo reads: read another repo's integration branch from the remote (`git fetch`, then `git show origin/stage:<path>`, or `origin/prod`), never the checked-out working tree (often stale). Never point one repo at another's unmerged feature branch (versions, refs, submodules, doc links).
- Infra capacity (no new VMs until the owner decides; resizing existing ones is allowed): `infrastructure-capacity`.
